# 고객 첫 화면과 사무실 전달 연출 조정

2026-11-20. 고객 상담과 2D 사무실을 같은 폭으로 배치하고, 상담 유형 선택을 줄여 첫 화면에서 선택할 수 있도록 조정했습니다.

## 배치

- 760px 이상에서는 상담과 사무실을 1:1로 배치합니다. 사무실의 실제 표시 폭이 함께 커지며, 팀 방을 누르는 업무 상세 기능도 유지합니다.
- 상담 유형을 작은 부품 그림이 있는 가로형 카드 두 장으로 바꾸고, 중복된 안내를 줄였습니다. 제목과 두 선택지를 먼저 보여 주며 음성 입력과 대화 기록은 바로 아래에서 사용할 수 있습니다.
- 첫 선택 화면의 대화 기록은 펼쳐 볼 수 있고, 글 입력창은 항상 보입니다. 상담을 고르면 기록은 기존처럼 펼쳐집니다. 첫 선택 전에는 반복되는 단계 표시를 생략하고, 설문부터 단계 표시를 보여 줍니다.
- 설문은 계속 음성 상담 패널 안에서 작성합니다. 입력 내용과 대화 기록은 상담 단계가 바뀌어도 유지합니다.
- 360px에서는 상담과 사무실을 세로로 배치합니다. 긴 설문과 후보 목록은 자연스럽게 스크롤합니다.

## 사무실 연출

- 실제 팀 간 전달 이벤트에 맞춰 직원이 서류를 들고 복도를 달려갑니다. 출발 팀과 도착 팀을 표시합니다.
- 전달 연출은 업무 상태와 분리합니다. 직원이 도착했다고 업무를 완료시키거나 진행률을 만들어 내지 않습니다.
- 기존 움직임 정지, 동작 줄이기 설정, 실행 중단과 요청 버전 변경을 존중합니다.

초기 검사에서는 데스크톱 페이지 높이가 959~993px로 목표를 넘었습니다. 첫 화면의 대화 기록을 접고 높이에 따른 간격을 조정한 뒤 다시 검사해 통과했습니다. 펼침·접기·글 전송, 후보·업무 상세·예산 이동 후 대화 유지, Escape 닫기와 포커스 복귀도 확인했습니다. 페이지 오류와 백엔드 호출은 0건입니다.

전달 연출은 1440·1024·360px에서 출발·복도·도착의 실제 좌표 변화, 다음 진행 이벤트 이후 유지, 정지 시 좌표 유지, 움직임 줄이기 설정을 검사했습니다. 업무 상세의 하단 버튼도 고정해 작은 화면에서 접근할 수 있게 했습니다.

실행하지 않은 요청 검사는 없습니다. 백엔드는 변경하지 않아 백엔드 검사는 실행하지 않았습니다.

캡처는 `frontend/test-results/split-office/` 아래에 저장합니다. 지난 캡처와 기존 검증 스크립트는 유지합니다.

- `customer/`: 4개 화면 크기의 캡처 48장과 `report.json`.
- `courier-departure-*.png`, `courier-corridor-*.png`, `courier-arrival-*.png`: 전달 구간별 캡처 9장.
- `delivery-verification.json`: 좌표·정지·이벤트 유지 검증 결과.

첫 화면, 작은 화면의 업무 상세, 달리는 직원의 전달 장면을 직접 열어 확인했습니다.

공통 계약·DB·백엔드·공유 설정·스냅샷은 변경하지 않았습니다. 패키지와 `src/`·`public/` 이미지 파일 추가도 없으며 Git 명령은 실행하지 않았습니다. 기존 테스트와 이전 검증 스크립트의 기대값은 변경하지 않았습니다.
