# 기존 게임형 오피스에 PC 상담 통합

## 실행과 로그인

`frontend`에서 `npm run dev`를 실행하고 `http://localhost:5173/`을 엽니다. 서버 연결 없이 기존 셸 안에서 계정 유형을 선택한 뒤 개인 PC 상담이나 기업 관리 화면으로 들어갑니다.

| 주소                      | 동작                                                   |
| ------------------------- | ------------------------------------------------------ |
| `/` 또는 `/?pc-consult=1` | 계정 선택과 시연 로그인 뒤 통합 개인/기업 화면         |
| `/?mock`                  | 기존 대본과 음성 상담 기록을 사용하는 자동 오피스 시연 |
| `/?office-gallery`        | 기존 개발용 오피스 상태 견본                           |
| `/?live`                  | 기존 백엔드 회사 목록과 상담 API를 사용하는 화면       |

로그인은 비어 있지 않은 아이디·비밀번호면 통과하는 시연입니다. 개인용 시연, 관리자로 시연, 상담원으로 시연 버튼으로도 입장할 수 있습니다. 기업 가입 코드는 `BW-1001`(가상전자), `BW-2002`(테스트컴퓨터)입니다. 실제 계정 생성·비밀번호 저장·인증 요청은 없습니다.

## 확인받은 배치와 구현

| 화면 폭 | 개인                                                                                             | 기업                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 1440px  | 기존 왼쪽 메뉴·상단 띠. 사무실과 음성 상담을 좌우로 배치하고 아래 `#results`에 PC 상담 전체 흐름 | 같은 셸의 왼쪽에 7개 메뉴. 본문에 선택한 메뉴. 오피스 메뉴에서 기존 사무실 한 개 표시 |
| 1024px  | 기존 반응형 배치에 따라 사무실, 음성 상담, PC 상담 순서                                          | 왼쪽 메뉴 폭을 줄이고 본문 폭 확보. 기존 사무실은 가용 폭에 맞춤                      |
| 360px   | 사무실, 음성 상담, PC 상담 순서로 세로 배치. 기존 하단 바로가기 유지                             | 하단 기업 메뉴 버튼으로 7개 메뉴를 펼침. 본문은 세로 배치                             |

PC 상담의 별도 헤더·페이지 껍데기는 통합 모드에서 숨겼습니다. 신규 조립과 부품 교체의 기존 설문·후보·예산·견적·승인·결제 자리 화면을 그대로 재사용합니다. 같은 셸의 기업 메뉴도 기존 관리 기능을 재사용하며 별도 사무실 그림을 렌더링하지 않습니다.

확인받은 배치안의 화면 순서를 유지했습니다. 360px 기업 메뉴는 7개를 한 줄에 압축하지 않고 펼치는 방식으로 구현했습니다.

## 진행 이벤트와 기록

- `ConsultDataSource`의 실제 결과와 상담 리듀서가 수락한 전이를 기존 `AgentEvent`로 변환합니다. `officeReducer`, `OfficeScene`, `officeCues`, `ChatPanel` 소스는 수정하지 않았습니다.
- 설문 확인은 상담팀의 `requirements.updated`, 후보 검색은 설계팀, 호환성 확인은 검증팀, 견적 생성·저장은 견적팀 이벤트로 표현합니다.
- 현재 스냅샷 검증은 순차 묶음 처리이므로 동시에 일하는 검증원은 1명입니다. 후보 수를 검증원 수로 꾸미지 않습니다. 실제 처리량은 진행 이벤트에 표시합니다.
- 후보 결과가 도착해야 검증·후보 정리 완료를 냅니다. 결과가 사무실 표시 대기열을 통과한 뒤 후보를 선택할 수 있습니다. 승인 전에는 입력 대기이며 `confirmQuote()` 성공 뒤에만 `run.completed`를 내 견적서가 출력됩니다.
- 표시 간격은 기존 `app/mockPace.ts` 설정을 사용합니다. 기본 700ms, `?pace=slow`는 2000ms, 숫자는 300–5000ms입니다. 중복 진행 알림만 합치며 시작·완료 전이는 유지합니다.
- 견적 변경 요청은 `requirement_version`을 올리고 `seq`는 이어갑니다. 이전 견적은 보존하고 새 버전은 재승인합니다.
- 고객의 유형·설문·부품·예산·변경·승인 선택은 기존 대화 패널에 고객 발화로 기록합니다. 팀 기록은 기존 `teamNotesForOffice`를 사용합니다. 결과를 기다리는 동안 조건이 바뀌어 버린 전이는 대화에 확정 기록으로 넣지 않습니다.
- 음성 받아쓰기·읽기 기능은 기존 패널 그대로입니다. 자유 발화는 요청 메모이며 조건을 자동 해석했다고 표시하지 않습니다. 실제 조건은 PC 상담의 선택 항목에서 반영합니다.
- 기업의 시연 상담·요약·이슈 이벤트도 같은 사무실 리듀서로 표현합니다. 상담 접수가 끝나면 설계·분석팀이 요약을 정리하고, 클레임 접수가 끝나면 검증팀이 유형과 담당 부서를 확인하는 흐름으로 기존 서류 이동 연출을 사용합니다. 실제 요약 저장·분류 이벤트가 도착해야 완료하며, PC 호환성 판정이나 견적 확정 이벤트는 생성하지 않습니다. 처리 버튼은 기존 고객·이슈 메뉴에만 둡니다.

## 데이터와 API

스냅샷, 데이터 어댑터, 간이 기준표와 API 제안은 변경하지 않았습니다. 개인 부품 가격은 테스트 가격이며 견적 저장은 메모리 시연입니다. 기업 가상 통계는 개인 부품 추천에 쓰지 않습니다. 판매량·벤치마크·누락된 사양을 생성하지 않았습니다.

간이 기준값·선정 이유·분류별 확인 불가 원인은 [이전 구현 보고](IMPLEMENTATION_REPORT.md#간이-기준표)에 보존했습니다. 특히 저장장치 연결 정보, 쿨러 소켓, 케이스 GPU 허용 길이 부족에 따른 확인 필요 후보를 그대로 노출합니다.

[API_PROPOSAL.md](API_PROPOSAL.md)는 후보 조회, 호환성 검증, 견적 생성, 견적 승인 4개 API 제안입니다. 아직 백엔드에 구현된 계약이 아닙니다.

## 검증

실행 위치는 `frontend`이며 Windows에서 같은 npm 스크립트를 `npm.cmd`로 실행했습니다.

| 명령                   | 결과                                             |
| ---------------------- | ------------------------------------------------ |
| `npm run typecheck`    | PASS, 종료 코드 0                                |
| `npm run lint`         | PASS, 종료 코드 0                                |
| `npm test`             | PASS, 21개 파일 · 235개 테스트                   |
| `npm run format:check` | PASS, All matched files use Prettier code style! |
| `npm run build`        | PASS, 70개 모듈, JS 493.27kB / gzip 145.21kB     |

기존 18개 파일·204개 테스트는 수정하지 않고 그대로 통과했습니다. 새 테스트는 개인 이벤트·큐 15개, 대화 기록 12개, 기업 오피스 연결 4개입니다. 설계팀에서 검증팀으로 서류 전달, 실제 동시 검증원 수, 저장 뒤 출력, 버전 증가, 지연 결과 취소, 배치 사이 표시 간격을 검사합니다.

통합 Playwright는 1440px·1024px 전체 흐름을 통과했고, 360px의 기업 메뉴 겹침을 수정한 뒤 360px 전체 흐름도 통과했습니다. `?mock` 자동 시연 완료·견적서 출력, `?office-gallery` 상태 견본도 PASS입니다.

| 실행 기록                                                     | 실제 결과                                                                                                      |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `node src/features/pc-consult/verification/verify-office.mjs` | 초기 전체 실행 FAIL. 1440px·1024px 전체 PASS, 360px 기업 메뉴 가림 발견. `office/integration-report.json` 보존 |
| `OFFICE_VIEWPORTS=360` 지정 후 같은 명령                      | 수정 후 PASS. 개인·교체·기업·키보드 검사와 mock/gallery 모두 통과. `office/integration-report-360.json`        |

기업 서류 전달 연결을 보완한 뒤에는 `OFFICE_VIEWPORTS=1440,1024`, `OFFICE_BUSINESS_ONLY=1`로 기업 오피스만 다시 검사해 PASS했습니다. 최종 기업 화면을 다시 촬영했으며 `office/integration-report-business-1440-1024.json`에 결과를 남겼습니다. 이 실행에서도 실제 서류 이동을 각각 24회·23회 좌표 샘플로 확인했습니다.

세 폭에서 가로 넘침 없음, 페이지 오류·백엔드 API 요청 0건을 확인했습니다. 각 스냅샷은 한 번씩 읽었습니다. 선택 발화·요청 메모·견적 변경·승인이 기존 대화 패널에 들어가고, 승인 전에는 출력물이 없고 저장에 성공한 뒤에 출력되는 것을 확인했습니다. 견적 변경 뒤에도 이벤트 순번은 증가하고 이전 견적 버전은 남습니다.

360px에서는 Tab/Enter로 개인 진입·유형 선택, 경고·승인 모달의 포커스 유지, 기업 7개 메뉴와 상담원 3개 제한 메뉴를 검사했습니다. 기업 서류 이동은 실제 `.office-cue-envelope` 좌표를 23회 측정해 이동을 확인했습니다. 클레임 분류 진행·완료 중 견적팀은 대기하며 출력물이 생기지 않습니다.

수정 중 검사 결과도 숨기지 않습니다. 최초 전체 Vitest는 샌드박스의 작업 프로세스 생성 제한(`spawn EPERM`)으로 FAIL이었고 동일 명령을 승인된 실행으로 다시 돌려 PASS했습니다. 첫 통합 브라우저 실행은 진행 중 개발 서버 HMR로 상담이 초기화돼 FAIL, 다음 실행은 실제 모바일 버튼 겹침으로 FAIL이었습니다. 기존 기대값을 결과에 맞춰 고치거나 테스트를 삭제·skip하지 않았습니다.

브라우저 재실행 명령입니다. 기존 설치된 Playwright와 저장소 내부 브라우저 캐시를 사용합니다. 새 패키지는 설치하지 않았습니다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) 'node_modules/.cache/pc-consult-browsers'
$env:TEMP = Join-Path (Get-Location) 'node_modules/.cache/pc-consult-temp'
$env:TMP = $env:TEMP
node src/features/pc-consult/verification/verify-office.mjs
```

특정 크기는 `$env:OFFICE_VIEWPORTS = '360'`을 지정해 재검사할 수 있습니다. 이때 별도 보고서를 남겨 이전 결과를 보존합니다.

통합 전 캡처는 `verification/office/before-1440.png`, `before-1024.png`, `before-360.png`입니다. 통합 후는 같은 폴더의 `after-{폭}-*.png`입니다. 개인 진입·설문·검증 중·AI 추천·확인 필요·예산 조정·승인 전 견적·승인 뒤 출력·견적 변경·교체 결제 안내, 기업 각 메뉴·오피스·상담원 권한을 포함합니다.

백엔드·DB·실제 인증·결제 검사는 실행하지 않았습니다. 이번 변경은 서버 없는 통합 화면입니다. 기존 백엔드용 `npm run e2e` 대신 통합 전용 Playwright 스크립트를 사용합니다. 실제 마이크로 받아쓰기·음성 재생을 하는 검사는 안 돌렸습니다. 기존 음성 패널 표시와 텍스트 요청 메모를 확인했고 음성 관련 기존 단위 테스트는 통과했습니다.

공통 계약·생성 타입·DB·backend·공유 설정·package/lockfile·스냅샷 두 파일·`.prettierignore`는 변경하지 않았습니다. 기존 테스트와 이전 스크린샷·검증 스크립트는 보존했습니다. Git 명령과 DB 접속은 실행하지 않았습니다.
