# 로그인 통합과 전체 화면 정리

2026-11-20. 별도 계정 선택 뒤 비슷한 소개와 로그인 화면을 다시 보는 흐름을 없애고, 밝은 색조로 로그인·기업·개인 화면을 정리했습니다.

## 달라진 흐름

- 첫 화면에 기업 로그인 폼을 바로 보여 줍니다. 기업/개인 버튼은 같은 화면 안에서 폼의 유형만 바꿉니다.
- 로그인 전에는 업무 메뉴·업무 상태·별도 셸 머리글을 표시하지 않습니다. 로그인 후 기존 기업 관리실이나 개인 상담실로 바로 들어갑니다.
- 로그인과 회원가입 사이, 기업과 개인 사이를 전환하면 폼을 새로 만들어 입력값과 비밀번호 표시 상태를 초기화합니다.
- 기업 인증번호, 시연 기업 선택, 관리자·상담원 권한, 개인 시연 진입은 유지합니다. 실제 인증이나 비밀번호 저장·전송은 없습니다.
- 모바일에서는 로그인 폼 뒤에 팀 소개를 접힌 상태로 둡니다. 데스크톱에서는 브랜드와 팀 비주얼 옆에 로그인 폼을 배치합니다.

## 전체 화면

- 흰 표면과 연한 회녹색 배경, 짙은 녹색 글자와 강조색을 사용합니다. 기능이 비슷한 버튼·입력창·카드의 모양을 맞췄습니다.
- 기업 메뉴의 글자·선택 표시와 상단 사용자 표시를 정돈했습니다. 현재 메뉴 제목을 상단에 표시합니다.
- 기업 홈의 반복 제목과 소개 높이를 줄였습니다. 큰 데스크톱에서는 사무실 지도 크기도 화면 높이에 맞춥니다.
- 인계함·정책·고객표·직원·판매 통계·피드백의 여백, 글자 대비, 상태 배지를 정리했습니다.
- 개인 상담은 기존 50:50 배치와 설문 창 내부 스크롤을 유지합니다. 후보는 그림·제품명·가격 순으로 읽히게 하고, 견적은 총액·부품 행·버전 이력을 구분합니다.
- 견적은 반쪽 화면에서도 작은 부품 그림·제품명·가격·변경 버튼이 가까이 보이도록 행 높이를 줄였습니다. 실제 사진이 없는 부품은 기존 분류 그림과 안내를 유지합니다.
- 키보드용 본문 바로가기 링크는 포커스를 받았을 때만 보이게 하고, 확인 불가 후보 안내의 과한 빈 공간을 줄였습니다.
- 사무실 애니메이션·실제 진행 이벤트·추천 규칙·기업 정책 적용 방식은 변경하지 않았습니다.

## 검사 결과

`frontend`에서 실행했습니다.

| 명령                   | 결과                                                  |
| ---------------------- | ----------------------------------------------------- |
| `npm run typecheck`    | PASS                                                  |
| `npm run lint`         | PASS                                                  |
| `npm test`             | PASS — 25개 파일, 271개 테스트                        |
| `npm run format:check` | PASS                                                  |
| `npm run build`        | PASS — 94개 모듈, 기존 500kB 초과 번들 안내 경고 있음 |

처음 `lint`는 신규 검증 스크립트의 미사용 전역 선언 1건 때문에 FAIL이었고, 해당 선언을 제거한 뒤 PASS했습니다. 첫 테스트 실행과 Playwright 실행은 샌드박스의 자식 프로세스 실행 제한(`spawn EPERM`)으로 실패하여 허용된 실행 환경에서 다시 실행했습니다. 테스트 내용이나 기대값은 바꾸지 않았습니다.

Playwright의 빠른 화면 검증은 네 크기(1440×900, 1024×900, 360×900, 1366×768)에서 64/64 PASS였습니다. 전체 흐름 검증은 144/144 PASS, 기존 시연·오피스 견본·키보드·움직임 줄이기 확인은 5/5 PASS입니다.

- 첫 화면의 로그인 폼은 하나이며, 로그인 버튼은 네 크기 모두 첫 화면 안에 보입니다.
- 빈 입력, 기업 인증번호 오류, 회원가입, 계정 유형 전환, 비밀번호 표시, 관리자·상담원 권한을 확인했습니다.
- 개인 신규 조립의 설문부터 실제 스냅샷의 8개 분류 선택, 견적, 승인 및 메모리 저장까지 확인했습니다.
- 1024px에서는 기본 정책을 그대로 두고 확인 불가 부품이 있는 견적의 승인 차단과 사람 인계 안내를 확인했습니다. 1440px·360px의 승인 시나리오는 기업 정책 화면에서 확인 불가·조건부 인계 설정과 자동 견적 한도를 먼저 변경한 뒤 진행했습니다. 기본 정책과 추천 데이터는 수정하지 않았습니다.
- 검사한 화면에서 가로 넘침, 브라우저 실행 오류, 백엔드 API 호출은 없었습니다. 비밀번호의 브라우저 저장도 없었습니다.

브라우저 검증 중 기업 인증번호 필드의 접근성 이름에 보조 문구가 포함된 문제를 발견해 명확한 `aria-label`을 추가했습니다. 또 새 검증 스크립트가 기본 정책의 인계 대상 견적도 승인할 수 있다고 잘못 가정해 실패했습니다. 제품 정책을 바꾸지 않고, 정책 변경을 포함한 승인 시나리오와 기본 정책의 승인 차단 시나리오로 나눠 바로잡았습니다. 기존 테스트와 기대값은 변경하지 않았습니다.

스크린샷과 브라우저 결과는 `frontend/test-results/ui-refresh/` 아래에 저장합니다. 이전 검증 스크립트와 캡처는 삭제하지 않았습니다. 이전 계정 선택 화면을 전제로 한 스크립트 대신, 의도적으로 바뀐 단일 로그인 흐름을 새 스크립트에서 검사합니다.

최종 흐름 스크린샷 79장과 기존 시연 확인 2장은 `frontend/test-results/ui-refresh/final/`에 있습니다. `report.json`에 크기별 검사 내역을, `smoke.json`에 추가 5개 확인 결과를 기록했습니다. 대표 캡처는 다음과 같습니다.

- `login-business-1440x900.png`, `login-business-360x900.png`: 단일 로그인
- `business-home-viewport-1440x900.png`: 기업 관리실 첫 화면
- `personal-workspace-1024x900.png`: 개인 상담과 사무실 배치
- `survey-360x900.png`: 내부 스크롤 설문 창
- `quote-1440x900.png`, `quote-360x900.png`: 부품 그림을 포함한 견적
- `saved-360x900.png`: 승인 후 시연 저장
- `mock-workspace.png`, `office-gallery.png`: 기존 자동 시연과 사무실 견본

백엔드 검사는 안 돌림: 화면과 로그인 진입 표현만 변경했습니다. 공통 계약·DB·백엔드·공유 설정·스냅샷은 변경하지 않았습니다. 패키지나 이미지 파일을 추가하지 않았고 Git 명령·화면 조작 도구를 사용하지 않았습니다.
