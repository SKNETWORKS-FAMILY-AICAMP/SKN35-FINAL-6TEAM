# 기업 운영 화면 개편 보고서

작성일: 2026-11-20. 기존 개인용 게임형 상담 화면과 PC 상담 엔진을 유지하면서 기업의 상품·정책 연결, 고객 상담 시험, 사람 인계, 운영 현황을 연결했습니다. 요청한 다섯 검사는 모두 통과했습니다.

## 1. 화면 구성과 메뉴

기업 메뉴는 다음 8개입니다. 기존 진입 값은 별도 중복 메뉴를 만들지 않고 새 메뉴로 연결합니다.

| 메뉴                | 하는 일                                                                           |
| ------------------- | --------------------------------------------------------------------------------- |
| 기업 홈             | 운영 지표, AI 팀 상태, 처리할 일, 활동 기록과 기존 2D 사무실                      |
| 상담 · 이슈         | 사람 확인이 필요한 상담, 인계 이유, 고객 대화와 팀 기록, 담당자와 처리 상태       |
| 고객 정보           | 가상 고객과 상담 이력, 차단 요청 및 권한에 따른 처리                              |
| 고객 화면 미리보기  | 같은 PC 상담 엔진으로 기업 정책을 시험하고 상담 기록을 인계                       |
| 고객 피드백         | 가상 피드백을 목적·조건·불만·이탈·인계 사유별로 보고 관련 정책으로 이동           |
| 판매 통계           | 기존 가상 판매·수요 시연 유지; 실제 상품 스냅샷의 판매량으로 오인하지 않도록 구분 |
| 상품 · 정책         | 실제 스냅샷 집계, 판매 정책, 두 기업 비교, 기존 문서 자료                         |
| AI 직원 · 사람 직원 | AI 업무팀의 이벤트와 사람 직원의 역할을 구분해 표시                               |

기존 `office`는 `home`, `documents`는 `catalog`, `employees`는 `teams`로 정규화합니다. 판매 통계와 상품·정책의 관리자 권한은 유지하며 상담원에게 관리 권한을 임의로 부여하지 않습니다.

확인받은 기능 배치는 유지했습니다. 메뉴의 묶음 이름은 화면에 맞게 '업무 공간 / 인사이트 / 기업 설정'으로 정리했고 모바일 메뉴만 아래의 포커스 가림 검증 결과에 따라 조정했습니다. 시연 제어와 발표 안내는 본문 위의 정상 흐름에 놓아 카드를 덮지 않습니다.

1440px에서는 너비 216px의 기업 사이드바, 1024px에서는 80px의 축소 사이드바를 사용합니다. 360px에서는 기업 메뉴를 문서의 일반 흐름에 놓고 펼쳐서 사용합니다. 처음의 모바일 하단 고정 메뉴가 정책 입력을 가리는 문제가 확인되어 일반 흐름으로 변경했습니다. 펼친 메뉴도 입력 영역 위를 덮는 고정 패널로 만들지 않습니다.

## 2. 3분 발표 안내와 실제 처리 상태

발표 모드는 7단계, 안내 시간 합계 180초입니다.

| 단계 | 안내 내용            | 권장 시간 |
| ---- | -------------------- | --------- |
| 1    | 기업 가입과 AI 팀    | 20초      |
| 2    | 상품 DB 연결 확인    | 20초      |
| 3    | 우리 회사 정책       | 20초      |
| 4    | 손님 상담과 팀 작업  | 35초      |
| 5    | 사람에게 인계        | 25초      |
| 6    | 피드백에서 정책 개선 | 25초      |
| 7    | 같은 상담 다시 실행  | 35초      |

단계 번호와 이전·다음 버튼은 화면을 이동시키는 수동 안내입니다. 경과 시간은 발표자 참고용이며 180초가 지났다고 상담이나 팀 작업을 완료시키지 않습니다. 설문 불러오기, 상담 시작, 인계, 정책 저장, 재실행은 사용자가 실제 버튼을 눌러 진행합니다. 마지막 비교도 실제 수신한 후보 결과를 사용합니다.

팀의 상태와 활동 기록은 같은 수신 이벤트를 바탕으로 만듭니다. 업무 하나가 끝난 `task.completed`를 고객 상담 전체의 자동 해결로 계산하지 않습니다. 기존의 상담 시작·인계·클레임·욕설 알림·판매·30초 전체 시나리오·초기화 시연 제어도 유지합니다. 이 가상 이벤트 재생은 실제 고객 처리 실적이 아닙니다.

## 3. 상품 연결과 기업별 정책의 실제 영향

상품은 제공된 읽기 전용 `parts.snapshot.json`과 `part_compatibility.snapshot.json`만 사용합니다. DB에 접속하지 않으며 JSON은 처음 필요할 때 `fetch`로 읽고 캐시합니다. 개인용 기본 소스와 기업 소스가 읽기 캐시를 공유하고, 견적·승인 영수증은 기업 코드별 메모리로 분리합니다.

`getCatalogSummary()`는 배열을 실제 집계합니다. 전체 부품은 9,917행, 제조사 호환성 근거는 23,032건입니다. 가격 기준일은 원본 메타의 2026-11-06, 추출 시각은 `2026-11-18T07:24:32.006880+00:00`입니다. 현재 값이 없는 판매량·재고를 0이나 추정치로 채우지 않고 관련 정렬은 비활성화합니다. 가격에는 테스트 가격 표시를 유지합니다.

| 시연 정책           | 가상전자 BW-1001 | 테스트컴퓨터 BW-2002                                              |
| ------------------- | ---------------- | ----------------------------------------------------------------- |
| 취급 범위           | 전체 8분류       | CPU는 AMD, RAM은 G.Skill·Kingston, 그 외 분류는 전체              |
| 취급 상품 수        | 9,917행          | 7,989행                                                           |
| CPU / RAM 행 수     | 492 / 2,659      | 119 / 1,104                                                       |
| 후보 순서           | 가격 낮은 순     | G.Skill → AMD → MSI → Kingston 우선, 같은 우선순위는 가격 낮은 순 |
| 할인 자동 응대 한도 | 3%               | 7%                                                                |
| 자동 견적 금액 한도 | ₩2,000,000       | ₩3,000,000                                                        |
| 미확인 호환성       | 담당자 인계      | 담당자 인계                                                       |
| 조건부 호환성       | 담당자 인계      | 조건을 표시하고 계속 진행 가능                                    |

이는 기업의 상품 범위와 영업 방침을 바꿔 끼우는 동작을 설명하기 위한 가상 설정입니다. 실제 판매 기업의 정책이나 보유 재고를 뜻하지 않습니다. 브랜드·부품명·가격·사양은 원본 스냅샷 값을 사용합니다. 두 기업 모두 8개 분류에 실제 상품 행이 있습니다.

같은 RAM 교체 설문, 예산 ₩500,000, 할인 5% 요청으로 전체 스냅샷을 실행한 결과입니다.

| 실행                              | 첫 통과 후보                                  | 테스트 가격 | 통과 후보 | 할인으로 인한 인계           |
| --------------------------------- | --------------------------------------------- | ----------- | --------- | ---------------------------- |
| 기업 A 기본 정책                  | Patriot Signature Line 16 GB `[30c8e1f84f14]` | ₩47,653     | 983개     | 필요: 5% 요청이 3% 한도 초과 |
| 기업 B 기본 정책                  | G.Skill Ripjaws 32 GB `[db7c4b3cabc2]`        | ₩108,938    | 427개     | 불필요: 7% 한도 이내         |
| 기업 A 한도를 7%로 저장 후 재실행 | 같은 Patriot 후보                             | ₩47,653     | 983개     | 해당 인계 사유 해제          |

이 설문은 실제 호환 간이 검증을 통과하는 보유 메인보드·파워와 RAM으로 구성합니다. 보유 RAM은 가능하면 실제 8GB 행을 선택해 기본 목표 16GB보다 낮게 만듭니다. 적절한 8GB 행이 없는 작은 견본에서는 추천품과 다른 실제 호환 행을 고릅니다. 일반 교체 상담도 이미 보유한 동일 `source_key`를 교체 후보에서 제외합니다.

할인율은 담당자 확인 여부를 판단하는 요청값입니다. 테스트 단가를 실제 할인 판매가처럼 바꾸지 않습니다. 후보 목록의 인계는 첫 추천 후보를 기준으로 계산하고, 선택한 전체 구성은 견적 단계에서 다시 검사합니다. 미확인 후보는 통과 목록과 분리하며 AI 추천을 붙이지 않습니다.

금지 표현은 직원 응답에서만 간이 문자열 규칙으로 치환합니다. 정책 화면에 적용 전·후 예시를 두었습니다. 고객 원문과 제조사 근거는 바꾸지 않으며 실제 LLM 응답 생성·검증을 구현한 것으로 표시하지 않습니다.

## 5. 템플릿에서 차용한 부분

저장소에 준비된 무료 소스의 일부 구조·스타일을 현재 React 화면과 색상 변수에 맞게 옮겼습니다. 전체 템플릿이나 새로운 프레임워크·패키지는 넣지 않았습니다.

| 출처                             | 차용 부분                                                                    |
| -------------------------------- | ---------------------------------------------------------------------------- |
| Tabler                           | 작업 목록과 활동 기록의 행 구성, 카드 여백·구분선, 상품 분류의 분할 막대     |
| TailAdmin 무료 HTML 템플릿       | 사이드바 메뉴 그룹, 지표 카드의 아이콘·제목·보조 설명 구성, 게이지 주변 배치 |
| PlainAdmin 무료 Bootstrap 템플릿 | 상태 배지의 모양·여백·의미별 색 구분                                         |

정확한 원본 경로·적용 파일·MIT 고지는 [THIRD_PARTY_NOTICES.md](./THIRD_PARTY_NOTICES.md)에 있습니다. 확인하지 않은 버전이나 커밋 번호를 만들어 적지 않았습니다. 템플릿의 고객명·제품·고정 숫자·사진·유료 구성요소는 가져오지 않았습니다.

## 8. 현재 한계와 연결하지 않은 부분

기업·개인 진입은 시연이며 실제 인증이나 회원 DB 저장이 아닙니다. 부품 후보와 호환성은 백엔드가 없는 스냅샷 간이 판단입니다. 실제 서버에 연결하려면 [API_PROPOSAL.md](./API_PROPOSAL.md)의 별도 계약 검토가 필요합니다.

정책의 `handoff.required`가 켜진 견적은 개인용 상담과 기업 미리보기 모두 자동 확정을 막습니다. 원본의 저장장치 포트·쿨러 소켓·케이스 GPU 공간 등에 정보가 부족해 최종 전체 검증에서 인계가 추가될 수 있습니다. 후보 단계에서 할인이 허용된다는 이유만으로 전체 견적을 승인 가능하다고 표시하지 않습니다.

기업 인계함에서 이슈를 해결해도 원래 고객 견적을 자동 승인하거나 원래 상담의 인계 상태를 해제하는 연결은 없습니다. 현재는 필요한 확인·정책 보완 후 같은 설문으로 새 상담을 실행하고 다시 검증해야 합니다. 재실행 후에도 미확인 자료나 정책 제한이 남으면 자동 확정되지 않습니다. 담당자 승인 API·CRM·실제 주문 저장은 향후 연결 대상입니다.

승인 가능한 시연 견적의 저장은 메모리뿐이며 새로고침하면 사라집니다. 정책 변경도 브라우저 시연 상태입니다. `backend/`, 공통 계약과 자동 생성 타입, DB·마이그레이션, 공유 설정 파일, 패키지·잠금 파일은 수정하지 않았습니다. 원본 스냅샷과 `.prettierignore`도 유지했습니다. Git 명령과 GitHub 쓰기 작업은 실행하지 않았습니다.
