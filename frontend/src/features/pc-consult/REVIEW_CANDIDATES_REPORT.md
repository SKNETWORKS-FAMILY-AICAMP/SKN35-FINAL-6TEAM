# 확인 필요 후보의 진행 흐름과 실제 선택 집계

2026-11-20. 신규 조립에서 연결 규격·지원 소켓·장착 길이 정보가 부족해 통과 후보가 없을 때, 선택할 수 있는 확인 필요 후보를 바로 보여 주도록 수정했습니다.

## 동작

- 통과 후보가 없고 확인 필요 후보가 있으면 목록을 기본으로 펼칩니다. 확인하지 못한 실제 검증 사유와 가격 낮은 순 기준을 먼저 보여 줍니다. AI 추천을 붙이지 않습니다.
- 통과 후보가 있는 단계는 통과 목록을 먼저, 확인 필요 목록을 접힌 상태로 아래에 둡니다. 둘 다 없을 때만 예산·조건을 바꾸는 빈 상태를 표시합니다.
- 경고 창은 확인 불가 항목만 보여 줍니다. 취소하면 같은 단계에 남고, 주의사항을 확인하고 선택하면 다음 부품으로 진행합니다.
- 견적의 해당 부품 행에 ‘확인 필요’와 사유를 표시합니다. 선택 당시 사유와 최종 구성 검증 사유를 보존하며, 승인해도 호환성 통과로 바꾸지 않습니다. 견적 변경은 새 버전에만 반영됩니다.
- 최종 구성에서는 서로 영향을 받는 부품도 확인 필요로 표시될 수 있습니다. 예를 들어 케이스 GPU 허용 길이가 없으면 GPU와 케이스의 검증 모두 확인 필요입니다. 기업의 선택 집계는 사용자가 실제 경고를 확인하고 선택한 부품만 셉니다.
- 기존 기업의 담당자 확인 정책은 그대로입니다. 견적까지 진행할 수 있지만 정책상 확인이 필요한 견적의 자동 확정은 차단합니다.

## 기업 화면 연결

- 개인 상담과 기업의 고객 화면 미리보기에서 승인된 `SELECT` 전이만 기록합니다. 경고 창을 열기만 하거나 취소한 경우, 목록을 다시 읽은 경우에는 추가하지 않습니다.
- 집계 키는 기업·상담·분류·부품 `source_key`입니다. 같은 상담에서 같은 부품을 반복 선택해도 한 건입니다. 다른 제품을 선택한 이력은 별도 건으로 남으므로 현재 견적의 부품 수와 다를 수 있습니다.
- 피드백의 ‘상품 정보 보강 필요’는 **실제 시연 집계**로 표시하고 기존 가상 분석과 분리합니다. 인계함에는 같은 상담의 선택 제품과 사유를 한 건으로 모읍니다.
- 기업별로 분리된 브라우저 메모리 기록입니다. 메뉴 이동·로그아웃 후 재로그인은 유지하고, 새로고침이나 해당 기업의 ‘처음으로’는 초기화합니다. 다른 기업의 기록은 함께 지우지 않습니다.
- 실제 선택 건수를 기존 가상 상담 KPI에 더하지 않습니다. 비밀번호·개인정보 저장이나 외부 전송을 추가하지 않았습니다.

`frontend`에서 실행했습니다.

| `node src/features/pc-consult/verification/verify-review-candidates.mjs` | PASS — 1440×900·360×900, 112항목, 캡처 30장                      |

Vitest의 기본 샌드박스 실행은 자식 프로세스 제한(`spawn EPERM`)으로 FAIL이었습니다. 허용된 실행 환경에서 같은 검사를 다시 실행해 PASS했습니다. 작업 중 새 기업 테스트 helper의 타입 누락을 수정했고, 기존 테스트 기대값을 변경하거나 건너뛰지 않았습니다.

브라우저 검증은 가짜 응답 주입 없이 제공된 스냅샷을 사용했습니다. 두 크기 모두 저장장치·쿨러·케이스를 확인 필요 후보에서 선택해 8단계를 마쳤으며, 기업 피드백은 0건에서 실제 선택 3건으로 증가했습니다. 인계함에는 같은 상담의 실제 선택 3건이 한 건으로 모였고, 선택한 제품명과 사유가 일치했습니다. 기본 기업 정책에 따른 견적 자동 승인 차단도 유지했습니다.

촬영 후 후보 상단 사유와 선택 버튼, 짧은 경고 창, 견적 행, 실제 피드백 영역, 인계 상세를 직접 확인했습니다. 검사한 화면에 가로 넘침·브라우저 실행 오류·백엔드 호출은 없었습니다.

스크린샷과 브라우저 결과는 `frontend/test-results/review-candidates/`에만 저장합니다. 기존 테스트·검증 스크립트·캡처는 삭제하지 않습니다.

- `storage-review-reasons-{1440,360}x900.png`: 빈 화면 대신 펼친 후보와 실제 누락 사유
- `cooler-review-candidate-{1440,360}x900.png`, `case-review-candidate-{1440,360}x900.png`: 바로 선택 가능한 확인 필요 후보
- `storage-warning-{1440,360}x900.png`: 짧은 확인 경고
- `quote-review-{1440,360}x900.png`, `quote-review-row-{1440,360}x900.png`: 부품별 확인 필요 표시
- `feedback-after-{1440,360}x900.png`: 실제 선택 3건 집계
- `actual-handoff-detail-{1440,360}x900.png`: 상담별 실제 인계 사유
- `report.json`: 후보 source_key와 가격, 단계별 진행, 집계 전후 검증 내역

공통 계약·DB·백엔드·공유 설정·원본 스냅샷은 변경하지 않았습니다. 새 패키지를 설치하지 않았고 Git 명령이나 화면 조작 도구를 사용하지 않았습니다. 백엔드 검사는 안 돌림: 이번 변경은 프론트엔드 시연과 메모리 저장 흐름입니다.
