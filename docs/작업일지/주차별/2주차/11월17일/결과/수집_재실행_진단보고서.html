다음 실행 순서

1

범위 합의

실제 앱 측정과 공식·합성 벤치마크를 구분합니다. 공식 벤치마크 포함은 사용자가 확인했습니다.

2

후보 재발견

짧은 출처명 검색, GitHub 연결 커넥터, 공식 데이터 포털, 브라우저 원격 조작을 사용합니다. Kaggle은 선택 사항입니다.

3

라이선스 확인

데이터와 코드의 조건을 따로 확인하고 귀속·재배포 조건과 버전을 기록합니다. 미확인 자료는 보류합니다.

4

정확한 파일 수집

고정 커밋/날짜와 정확한 파일만 받고 크기·SHA-256·출처 메타데이터를 함께 보관합니다.

5

비교 조건 정리

벤치마크 버전·OS·기기·해상도·모델·workload가 같은 결과끼리 비교하고 측정·추정값을 분리합니다.

6

RAG 자료 수집

완성 PC 한 대를 미리 정하지 않습니다. 지원 부품 카탈로그와 호환 규칙에 제조사 공식 문서를 연결합니다.

  • 메모리: DDR 세대·속도·모듈 구성·지연시간

  • 보드별 메모리 QVL·지원 속도, 쿨러 소켓 지원·높이 확인이 별도로 필요
  • 가격은 USD이며 2025년 스냅샷이므로 현재가로 간주하면 안 됨

사용자·팀 쪽에서 필요한 확인

  1. 진봉 님과 후보 기준 합의: DAWbench 테스트 세션, Puget 공개 DB, Blender 렌더 데이터처럼 성격이 다른 자료를 해당 분야 평가 후보로 인정할지 확인해 주세요. 팀원에게 메시지를 보내지는 않았습니다.
  2. 부품 카탈로그 범위: 사용자별로 PC가 구성되므로 특정 완성 PC 모델은 필요하지 않습니다. 추천 시스템이 다루는 CPU·GPU·메인보드·메모리·파워·케이스·쿨러 등 부품 카탈로그가 정해지면 그 제품군의 제조사 문서와 호환 정보를 모을 수 있습니다. 아직 카탈로그가 없으면 대표 부품 범위를 먼저 제안하겠습니다.
  3. Kaggle은 선택 사항: Kaggle 자료가 꼭 필요하면 사용자 PC에서 공식 CLI 설치와 로그인이 필요합니다. API 키는 대화나 프로젝트 파일에 붙이지 말고 로컬 자격 증명으로만 설정합니다. 현재 확보한 세 분야 자료에는 Kaggle 설정이 필요하지 않습니다.
