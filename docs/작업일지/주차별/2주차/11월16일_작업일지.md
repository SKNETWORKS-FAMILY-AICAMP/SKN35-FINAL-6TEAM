- 상태: 일부 데이터 표본 확보. 나머지 분야 및 RAG 공식 문서는 후보 검토 중

## 오늘 한 일

- Kaggle·Hugging Face·GitHub 공개 후보를 찾고, 출처·버전·라이선스를 검토한 정확한 파일만 수집하는 Python 봇을 준비했습니다.
- `discover` 단계는 후보 메타데이터만 기록하고, 실제 수집은 manifest에 파일 경로·고정 revision·이용 조건을 적고 승인 상태로 둔 경우에만 실행하도록 구성했습니다.
- Blender Open Data 스냅샷은 ZIP을 통째로 풀지 않고 JSONL을 스트리밍해 Blender 4.0 이상 기록 CSV를 만드는 처리기를 마련했습니다.
- 성능 평가 자료와 RAG 근거 자료를 분리했습니다. 완성 PC를 사전에 고정하지 않고 지원 부품 카탈로그와 제조사 공식 호환성 문서를 연결하는 방향으로 정리했습니다.

## 크롤링 실패와 한계

- 첫 자동 탐색은 36건 오류로 후보를 찾지 못했습니다. Hugging Face·GitHub DNS 실패 24건, Kaggle CLI/인증 환경 부재 12건이었습니다.
- 네트워크 재시도에서도 오류 14건이 남았습니다. Kaggle CLI 부재 12건, GitHub API 403 2건입니다. 긴 검색어를 짧은 고유명사 중심으로 바꾼 뒤 Hugging Face 후보 메타데이터 11건을 찾았지만 분야 오분류가 있어 수동 검토가 필요합니다.
- Kaggle은 이 실행 환경에 공식 CLI와 인증이 없어 탐색·다운로드하지 않았습니다.
- 검색 결과의 라이선스 표시는 승인 근거가 아닙니다. 정확한 파일·버전·원출처·측정 조건과 이용 조건을 사람이 확인해야 합니다.
- RAG 부품 후보 [docyx/pc-part-dataset](https://github.com/docyx/pc-part-dataset)는 README·스키마·라이선스만 읽기 전용으로 검토했습니다. README 기준 66,778개 부품이지만 2025년 7월 스냅샷이며, 원천 데이터 재사용 조건과 호환성 필드 보강이 필요합니다. 아직 다운로드하지 않았습니다.

## 내일 할 일 · 11/17

1. 사용자와 RAG 공동 담당자가 후보 분야·원본 링크·이용 조건을 다시 확인합니다.
2. 사용자가 확인한 출처만 조회하거나 정확한 파일을 추가로 내려받습니다. 확인 전에는 크롤링·수집 범위를 넓히지 않습니다.
3. 다운로드한 경우에만 고정 revision, 출처, 라이선스, 수집일, SHA-256을 기록합니다.
4. RAG는 부품 카탈로그 후보와 제조사 공식 매뉴얼·사양·호환성 근거를 분리해 목록화합니다.

## 저장소 반영 범위
