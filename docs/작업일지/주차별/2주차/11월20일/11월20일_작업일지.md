## 결과와 한계

- 기본 규약은 **9건 중 8건 통과·1건 실패**, 하위 비교 요소는 **169개**입니다. 내역은 환경 계약 1개·API 불일치 경로 12개·이벤트 스키마 119개·열거형 35개·미정의 필드 1개·UTC 정규화 1개입니다.
- 등록된 ALL은 BASE를 포함해 **122건 중 121건 통과·1건 실패**, **subtest 16건 통과**, 하위 비교 요소 **552개**입니다. ALL XML의 `tests=138`은 testcase 122개와 subtest 16개를 포함한 수치이며 하위 552개는 추가 실행 건수가 아닙니다.
- ALL에는 직접 관측한 하위 검증이 없는 테스트 **2건**이 있습니다. 하나는 자식 프로세스 내부에서 검증하고, 다른 하나는 금지된 서비스 호출이 없으면 통과하는 방식입니다. 관측 수 0으로 구분해 상위 통과와 상세 수집 완전성을 혼동하지 않도록 했습니다.
- API 실패는 기존 수집기가 `PREFIX = "/api/pc-consult"`를 `/PREFIX/...`로 기록하는 한계와, 상수를 해석한 실제 경로도 저장 `contracts/openapi.json`에서 찾을 수 없는 상태를 함께 보여줍니다. 수집기 본체·공통 계약을 수정하거나 기존 실패를 통과로 바꾸지는 않았습니다.
- Excel 변환 회귀검사 6건, 실행 분류 회귀검사 5건, 하위 기록 확인 조건 4개를 검증했습니다. 자동 수집기 회귀 견본 8개는 정상 5개·의도적 실패 3개가 기대대로 기록됨을 확인했습니다. 변경 Python 파일 Ruff 검사, Excel 재열기, XML과 Excel의 상위 122개·하위 552개 정합성 확인도 통과했습니다.
- 공유용 `config.py`는 아직 `Path("프로젝트 폴더 경로")` 안내값이며 신규 상담 테스트 8개도 미분류 상태입니다. 이번 ALL 검증은 설정·분류를 임의로 바꾸지 않고 검증용 호출에서 현재 프로젝트 경로와 등록 대상을 지정했습니다. 옵션 없는 전체 실행의 사전 검사가 통과했다는 뜻은 아닙니다.
- 기본 규약 실행 명령은 `python -B tests/unit/run.py --test-id unit-base-common-contract-001`입니다. 일반 `pytest --junitxml=...` 직접 실행은 전용 실행기를 거치지 않으므로 Excel이 자동 생성되지 않습니다.
- 상세 수집은 매개변수화 입력만 기록하고 fixture 전체·일반 지역변수·실제 환경변수는 수집하지 않습니다. 비밀값 관련 표현식과 비교값을 가리지만 기존 pytest 실패 traceback 전체를 제거하는 기능은 아니므로 결과 공유 전 확인이 필요합니다.
- 이번 상세화에서 업무 테스트의 기대값·공통 계약·DB 스키마·의존성·잠금 파일은 변경하지 않았습니다. 모듈·시스템·인수 테스트는 실행하지 않았습니다.
