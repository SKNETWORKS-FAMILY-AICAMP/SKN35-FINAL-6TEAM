# 2주차 작업일지 · 2026-11-18

- 프로젝트: BUILDWISE 최종 프로젝트
- 작업자: ssu 브랜치 담당
- 작업 범위: 기획 변경 회의 피드백 반영(B2B 고객센터 자동화), 아키텍처 초안, 판매자 관리 화면 정리·목업 프롬프트, 데이터 봇 검수
- 상태: 모두 팀 검토 전 초안. 팀 기획서 원본은 수정하지 않고 사본에 반영

## 오늘 한 일

- 기획 변경 회의 피드백(타깃 고객 B2B, 로그인 → 설문 → 상담, 음성 주력·채팅 보조, 분야별 상담, 클라우드 삭제, 다중 사용자, 고객센터 관리 자동화·모니터링, 세일즈 자동화, 기업 사용자용 2D 부서)을 기획서 수정안으로 정리했습니다.
- 팀 기획서 구글 문서의 사본을 만들어 수정안을 반영하고, 새 구조도·기능 변화 그림·회의 스케치 3장을 넣었습니다. 핵심만 담은 A4 2쪽 요약 문서도 따로 만들었습니다.
- 바뀐 범위에 맞춰 아키텍처 초안을 썼습니다. 기존 구조(React · FastAPI 단일 프로세스 · PostgreSQL+pgvector · SSE)는 유지하고 음성 처리, 전달·업무 보조 에이전트, 기업 관리 화면, 기업 구분(company_id)을 붙이는 안입니다.
- 판매자 고객센터 관리 화면을 정리했습니다. 로그인(기업은 인증번호 추가), 메뉴 7개, 관리자·상담원 권한, 2D 오피스(보기 전용)를 정하고, 클릭하면 움직이는 목업용 프롬프트를 썼습니다.
- 11월 17일 데이터 수집 봇 코드와 산출물을 팀 DB 스키마와 대조해 검수했습니다.

## 정한 것 (판매자 화면)

| 항목 | 결정 |
|---|---|
| 기업 인증번호 | 기업마다 미리 정한 번호(시연용 고정값) |
| 관리자·상담원 역할 | MVP에 포함 |
| 악성 사용자 | 욕설만 자동 감지, 블랙컨슈머는 관리자가 직접 차단 |
| 재고 | 재고 수량 관리는 하지 않고 판매 통계로 인기 상품만 파악 |
| 상담·이슈 현황 | 2D 오피스와 분리한 별도 메뉴 |

## 결과와 한계

- 기획서 수정은 사본에만 했습니다. 팀 원본 반영은 팀 확인 뒤에 합니다.
- 아키텍처·화면 문서는 초안입니다. STT·TTS 엔진, MySQL→PostgreSQL 전환 시점, 추가 메뉴(홈 대시보드·문서·정책 관리·직원 관리) 채택은 팀 확인이 필요합니다.
- 데이터 봇 산출물은 팀 DB에 바로 적재할 수 없습니다. part_id 생성 방식과 parts 테이블 제약(KRW·가격 출처)이 달라 매핑 단계가 필요합니다(DB 담당과 확인 예정).
