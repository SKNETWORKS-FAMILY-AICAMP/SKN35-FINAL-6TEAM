## 오늘 한 일

### 지금 음성 흐름 점검

- 말이 끝났는지를 침묵 1초로만 판단합니다.
- 상담 답(`/api/pc-consult/sessions/{id}/messages`)은 스트리밍 없이 한 번에 와서, 답 전체가 와야 읽기 시작합니다.
- 읽는 동안 마이크를 꺼서 중간에 끼어들 수 없습니다.
- 그래서 한 턴마다 말 끝 1초, 답 전체, 읽기 시작을 차례로 기다리고 그동안 아무 소리가 없습니다.

### 음성 엔진 1차 (`lsh/voice-realtime`, `lsh/office-pc-consult` 기준)

- 말 끝 판정: 마지막 어절을 보고 기다리는 시간을 바꿉니다. "추천해 주세요"처럼 끝맺은 말은 0.55초, "그래픽카드는"처럼 이어질 말은 1.4초, 애매하면 0.8초입니다.
- 즉시 반응: 음성으로 보낸 뒤 0.35초 안에 답이 없으면 "네, 잠시만요." 같은 짧은 말을 먼저 읽습니다. 대화 기록에는 남기지 않습니다.
- 문장 단위 읽기: 답을 문장으로 나눠 첫 문장부터 바로 읽습니다. 기기에 있는 한국어 음성을 먼저 고르고, 읽기 신호가 오지 않으면 그 문장을 건너뜁니다.
- 끼어들기: 읽는 중에 말하면 멈추고 다시 듣습니다. 스피커 소리를 사용자 말로 잘못 알아들을 수 있어서, 그 비율을 재기 전까지는 주소에 `?barge-in` 을 붙였을 때만 켭니다.
- 턴 시간 기록: 주소에 `?voice-debug` 를 붙이면 구간별 지연 표와 JSON 내보내기가 보입니다. 시각 숫자만 남기고 말한 내용은 남기지 않습니다.
- 개발용 실험 화면: `npm --prefix frontend run dev` 뒤 `http://localhost:5173/?voice-lab`. 백엔드 없이 가짜 대화 서버로 음성 흐름 전체를 돌려 볼 수 있습니다. 개발 서버에서만 열리고 빌드 결과에는 들어가지 않습니다.
- 공통 계약, DB, 공유 설정은 건드리지 않았습니다. `useChat` 은 받는 api 타입만 좁혔습니다(동작 변경 없음).
